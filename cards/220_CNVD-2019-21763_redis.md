# 220｜Redis 4.x+ 模块/Rogue Master（CNVD-2019-21763）

- 镜像：`vulfocus/redis-cnvd_2019_21763`
- 题库端口：`6379`
- **编号校正：**CNVD-2019-21763 是 Redis **4.x+ modules** + rogue master / FULLRESYNC 落 `.so` 再 `MODULE LOAD`（WCTF2019 / Pavel Toporkov），公开转载无 CVE。不是 crontab/`authorized_keys` 经典写文件（常标 CNVD-2015-07557），也不是 CVE-2015-4335（Lua EVAL）。[S1][S4]

## 一句话打法

未授权 Redis（6379）被设成攻击者 rogue 节点的副本，复制写入恶意 module，`MODULE LOAD` 后得到新命令执行 OS 命令。[S3][S4]

## 操作步骤

1. 对 `6379` 确认无 `requirepass`。本链是 Redis 协议，不是 HTTP。[S3]
2. 用公开工具（redis-rogue-server / redis-rce）让目标 `SLAVEOF` 到攻击者 rogue 端口，把 `.so` 同步过去再 `MODULE LOAD`。[S3][S4]
3. 成功信号：新 module 命令能跑系统命令，或 `INFO` 显示 replica/module。[S3]
4. 攻击者 **回连端口必须被 Redis 主机访问到**。[S3]

## 本题特有排坑

- Redis 2.x/3.x 没有 modules，本 CNVD 的 module 原语不成立；不要改写成 crontab 当成本编号。[S1]
- 不要标成 CVE-2015-4335。[S5]
- 中途失败的 `CONFIG SET dir/dbfilename` 可能把实验环境写坏。[S3]
