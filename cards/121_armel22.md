# 121｜vulfocus/armel22（ARM EABI 环境识别）

> **题目性质：**环境/架构识别，不是已知 CVE 利用题。题库镜像 `vulfocus/armel22:latest`，内部端口 `5535`。Hub 无漏洞说明。[S1]

## 操作步骤

1. 识别 5535 端口上开放的服务：[S2]

```bash
nmap -Pn -sV -p 5535 <IP>
nc -nv <IP> 5535
```

按识别出的协议使用题目提供的入口连接；不要仅凭端口号猜服务或凭据。实际连接用 Vulfocus 映射端口，不要把内部 5535 当成外部端口。[S1]

2. 获得题目允许的 shell 后，确认运行系统和架构：[S3][S4][S5]

```bash
uname -a
uname -m
cat /etc/os-release
dpkg --print-architecture
```

3. 按运行时输出选择对应架构的程序。题名/镜像里的 **armel** 是 Debian 对 32 位 ARM EABI（软浮点、小端）移植的名称，**不是** arm64/aarch64，也不是 armhf。[S5]

## 本题特有排坑

- `uname -m` 在 ARM 32 位上常见 `armv5tel`/`armv6l`/`armv7l`；`dpkg --print-architecture` 在本题镜像上应接近 `armel`。两者名称不同，以包架构名为准去选二进制。[S3][S4][S5]
- 不要套用第005题 `armhf22`（硬浮点）或 arm64 的程序包；三者 ABI 不兼容。[S5]
- 5535 是题库内部端口；从 Vulfocus 页面显示的映射地址访问。[S1]
