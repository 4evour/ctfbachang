# Vulfocus 题解卡片库

面向授权的 Vulfocus 靶场与 CTF 练习，按题目整理可复核的漏洞利用步骤、关键排坑和参考来源。卡片用于快速查阅与复现思路，不收录 Flag，也不替代对目标版本和环境的确认。

## 快速开始

1. 在 [`index.csv`](index.csv) 中按题名或 CVE 查找题目，确认卡片路径和题库端口。
2. 打开对应卡片，先核对镜像、版本、入口和利用前提，再按步骤操作。
3. 遇到 `[S#]` 标记时，查看卡片末尾的来源链接；来源的具体用途见对应的 `_meta.md`。
4. 题目整理状态和后续安排以 [`batches/progress.csv`](batches/progress.csv) 为准。

卡片中的端口、路径、参数和 Payload 可能依赖特定镜像或版本。请仅在自己有权测试的靶场环境中操作；不要把卡片步骤直接用于未授权目标。

## 仓库内容

| 路径 | 内容 |
| --- | --- |
| [`cards/`](cards/) | 逐题利用卡片：打法、操作步骤、成功信号、特有排坑和来源编号 |
| [`sources/`](sources/) | 逐题来源清单，记录原文链接及其支持的具体结论或步骤 |
| [`index.csv`](index.csv) | 题目索引：题名、CVE、端口、卡片路径和来源数；尚未形成卡片的条目可能没有卡片路径 |
| [`batches/progress.csv`](batches/progress.csv) | 逐题整理状态及后续安排 |
| [`WORK_LOG.md`](WORK_LOG.md) | 重要规则调整和阶段记录 |

原始题库、样本压缩包、个人实战笔记及来源原文副本不纳入公共仓库；其中部分本地文件名已列在 `.gitignore` 中。

## 如何阅读卡片

卡片尽量保持短小，通常按以下顺序组织：

- **一句话打法**：指出漏洞入口和核心利用思路。
- **操作步骤**：按实际顺序给出请求、参数或命令，并标出成功信号。
- **本题特有排坑**：记录会导致该题利用失败的版本、端口、编码或参数差异。
- **来源**：用 `[S#]` 将关键步骤与公开题解、PoC 或官方资料对应起来。

来源编号在卡片和来源清单中保持一致。`index.csv` 的来源数只统计有用且不重复的外部链接；题库字段等本地资料不计入来源数。来源清单会说明链接支持什么，便于读者自行核对适用条件。

## 整理约定

- 优先查找与题目编号、产品和版本直接对应的题解或 PoC，并用厂商/项目官方资料核对漏洞边界与修复情况。
- 只写能由来源支持的操作步骤和本题特有条件；证据不足时明确说明，不拼凑通用步骤。
- 不记录 Flag、Flag 路径或搜索 Flag 的命令。没有真实比赛实例时，卡片止于漏洞利用成功信号。
- 不下载整篇原文，也不对靶场进行实测；卡片提供的是基于公开资料整理的复现线索。
- 已完成卡片原则上冻结。新规则用于后续整理；只有用户明确要求，或发现会误导解题的具体事实错误时，才针对性修改旧卡片。

## 维护进度

`index.csv` 用于定位题目和卡片，`batches/progress.csv` 是逐题状态的唯一依据。开始整理新题时，只读取该题的索引行、卡片和来源清单，以及确有必要的相关资料；完成后同步更新卡片、来源清单和进度记录。并行整理时，每位执行者只修改自己负责的卡片与来源目录，共享索引和进度表由主流程统一更新。
