# 223｜Shiro rememberMe Padding Oracle 反序列化（SHIRO-721 / CVE-2019-12422）

- 镜像：`vulfocus/shiro-721`
- 题库端口：`8080`。题库题名无 CVE；公开资料对应 **CVE-2019-12422 / SHIRO-721**。[S1][S2][S6]

## 一句话打法

先登录拿到**合法** `rememberMe` Cookie，再对 AES-CBC 做 Padding Oracle，把 ysoserial 序列化字节加密成可通过填充校验的 Cookie，服务端解密后走 `ObjectInputStream`。[S1][S3][S4]

## 操作步骤

1. 确认是 **Padding Oracle**，不是第143题默认密钥（Shiro-550 / CVE-2016-4437），也不是第05/096/097题路径鉴权绕过。未登录常见 `Set-Cookie: rememberMe=deleteMe`。[S1][S3][S4]

   ```powershell
   curl.exe -i "http://<靶场IP>:8080/"
   ```

2. 打开登录页（公开复现常见 `/login.jsp` 或 `/account`），用页面给出的账号**勾选 Remember Me** 登录。Apache samples 常见 `lonestarr` / `vespa`。从响应 Cookie 里取出整段 Base64 `rememberMe`（不要用 `deleteMe`）。[S3][S4][S5]

3. 本地用 ysoserial 生成**尽量短**的 gadget（公开示例 `CommonsBeanutils1` + `touch /tmp/success`）。Windows 不要用 PowerShell 5 的 `>` 写二进制。[S3][S4]

   ```text
   java -jar ysoserial.jar CommonsBeanutils1 "touch /tmp/success" > payload.class
   ```

4. 用合法 Cookie 当前缀跑 Padding Oracle（公开脚本 `python2 shiro_exp.py <url> <rememberMe> payload.class`）。Oracle 特征：填充错误会再下发 `rememberMe=deleteMe`，填充正确则不会。脚本常要删掉 `JSESSIONID`，只带 `rememberMe`。[S3][S4]

5. 把脚本打印的新 Cookie 发回同一入口。成功信号是命令副作用（公开复现为容器内 `/tmp/success`），HTTP 往往无回显；填充打通时响应不再带 `deleteMe`。[S1][S3]

## 本题特有排坑

- **必须先有合法 rememberMe**。不知道密钥时不能套第143题 `kPH+bIxk5D2deZiIxcaaaA==`；721 是改密钥之后、CBC 填充侧信道。[S1][S2][S3]
- Padding Oracle 按块爆破，公开复现常写 **约 1 小时级**；payload 越短越快。不要当成“脚本卡住了就换 550”。[S3][S4]
- 官方 JIRA 影响 **1.2.5、1.2.6、1.3.0–1.3.2、1.4.0-RC2、1.4.0、1.4.1**，修到 **1.4.2**（默认 cipher 改 GCM）。NVD 写作 1.4.2 之前默认 rememberMe 可被 padding 攻击。[S1][S2]
- 产出是反序列化执行，不是 `/xxx/..;/`、`;/`、`%0a` 那类越权。[S1]
